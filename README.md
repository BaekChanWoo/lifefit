1.	프로젝트 개요 및 문제 정의
1.1.	기획 배경
현대인은 바쁜 일상 속에서 건강한 생활 습관을 꾸준히 유지하기 어렵다. 특히 운동, 식단, 수면 등 다양한 건강 요소를 혼자서 체계적으로 관리하기란 쉽지 않으며, 꾸준함을 유지하기 위한 동기 부여 또한 부족한 경우가 많다. 게다가 신뢰할 수 있는 건강 정보를 얻거나, 비슷한 목표를 가진 사람들과 소통할 수 있는 플랫폼이 부족하다는 점 역시 개인 건강 관리의 큰 걸림돌이다.

이에 따라, 본 프로젝트는 단순한 건강 기록을 넘어, 사용자 간 소통과 교류를 중심으로 한 헬스케어 커뮤니티 환경을 조성하고자 한다. 건강 정보를 공유하고, 서로의 습관을 응원하며, 함께 운동 목표를 실천해 나갈 수 있는 커뮤니케이션 중심의 모바일 애플리케이션을 기획하게 되었다.

1.2.	목표
본 프로젝트의 궁극적인 목표는 지속적인 동기 부여와 상호 소통을 기반으로 한 건강한 생활 습관 형성을 유도하고자 한다. 기존 헬스케어 앱들은 일방향적인 기록 기능에 머무르거나 단기적 동기 부여에 의존하는 경향이 있는 반면, 본 앱은 커뮤니티와 커뮤니케이션 기능을 핵심 요소로 통합함으로써 장기적인 습관 형성을 가능하게 하고자 한다. 이를 위해 우리는 다음의 세 가지 하위 목표를 설정하였다. 이러한 목표들을 통해 본 애플리케이션은 단순한 건강관리 도구를 넘어, 사용자 간의 유대감 속에서 함께 성장하고 회복하는 건강 생태계를 조성한다.

1.2.1.	일상 속 건강관리의 구조화 : 사용자는 수분 섭취, 수면, 운동, 식단 등 주요 건강 요소를 손쉽게 기록하고 시각화된 데이터를 통해 자신의 건강 패턴을 인식할 수 있다. 이를 통해 사용자는 단편적인 실천이 아닌 데이터 기반의 자기주도적 건강관리를 경험할 수 있다.
1.2.2.	사회적 동기 부여의 유도 : 커뮤니티 기반 기능을 통해 사용자는 건강 목표나 운동 계획을 다른 사용자와 공유하고, 운동 메이트를 찾거나 챌린지에 함께 참여할 수 있다. 이 과정에서 사용자 간 피드백과 응원이 발생함으로써, 내적 동기뿐만 아니라 사회적 동기에 의한 지속성이 강화된다.
1.2.3.	신뢰할 수 있는 건강 정보의 제공 및 교류 : 검증된 건강 정보를 주기적으로 제공하고, 사용자가 직접 경험을 나눌 수 있는 커뮤니티 공간을 마련함으로써 정보의 신뢰성과 상호 학습 효과를 함께 달성하고자 한다.

1.3.	기대효과

1.3.1.	사용자 관점
→ 혼자 운동하는 어려움 해소 및 동기 부여: 번개 기능을 통해 함께 운동할 사람을 쉽게 찾음으로써, 사용자들이 꾸준한 운동 습관을 형성할 수 있다.
→ 건강 데이터의 시각화를 통한 자기관리 능력 향상: 수면 시간, 걸음 수 등의 데이터를 그래프 형태로 확인함으로써, 자신의 생활 패턴을 쉽게 인식하고 조절할 수 있다.
→ 모바일 기반의 간편한 건강 관리: 앱 하나로 다양한 건강 관리 기능을 제공하여, 복잡한 절차 없이 간편하게 일상 속 건강 관리를 실천할 수 있다.
→ 사용자 중심의 직관적인 UI/UX 경험: 누구나 쉽게 접근하고 사용할 수 있는 인터페이스를 통해 사용자 만족도를 높인다.

1.3.2.	개발자 관점 

→ Firebase, Flutter, Node.js 등 다양한 기술 스택 경험: 프론트엔드와 백엔드, 클라우드 기반 데이터베이스 연동 등 다양한 영역의 실무 기술을 체계적으로 습득할 수 있다.
→ 실시간 데이터 처리 및 상태 관리 기술 습득: 실시간 신청 기능과 상태 반영을 구현하면서 효율적인 상태 관리 기법에 대한 이해를 높일 수 있다.
→ 비정형 데이터와의 연동 및 시각화 경험: 수면 및 걸음 수 데이터를 시각적으로 표현하는 기능을 통해, 데이터를 사용자 친화적으로 가공하는 방법을 배울 수 있다.
→ REST API 통신과 인증 처리 구조 이해: Flutter에서 Node.js 서버 및 Firebase Auth와의 통신을 통해, 실제 서비스 환경의 백엔드 로직과 인증 구조를 이해하게 된다.
→ UI/UX 및 기능 개선을 위한 반복적 개발 프로세스 경험: 사용자 피드백과 테스트를 기반으로 한 기능 개선 작업을 반복하며, 실전형 개발 역량을 키울 수 있다.

2.	기술적 접근 및 구현 
2.1.	회원가입 로직

(1)	 Flutter에서 회원가입 폼 작성 및 전송
- 사용자는 아이디, 비밀번호, 이름 등의 정보를 입력 후 서버로 전송한다.

(2)	  Node.js 서버에서 사용자 정보 저장
- 서버는 해당 정보를 MySQL에 저장한다.
- 동시에 Firebase Admin SDK를 통해 Firebase 사용자도 생성한다.

(3)	 Firebase 사용자 생성 후 커스텀 토큰 발급
- admin.auth().createCustomToken(uid) 메서드를 사용해 커스텀 토큰을 발급한다.
- 발급된 토큰은 Flutter 클라이언트로 반환된다.

(4)	 Flutter에서 커스텀 토큰으로 로그인 처리
- FirebaseAuth.instance.signInWithCustomToken(token)을 사용해 Firebase에  로그인한다.
- 이후부터는 Firebase의 인증된 유저로 앱을 이용할 수 있다.

2.2.	 로그인 로직
(1)	Flutter에서 로그인 정보 입력 후 서버 요청
- 아이디와 비밀번호를 입력하고 서버로 전송한다.
(2)	 Node.js에서 사용자 검증
- MySQL에서 해당 정보를 조회해 인증을 수행한다.
(3)	 인증 성공 시 커스텀 토큰 재발급
- 해당 사용자 UID로 Firebase 커스텀 토큰을 생성하여 반환한다.
(4)	 Flutter에서 로그인 처리
- 마찬가지로 signInWithCustomToken()을 통해 Firebase에 로그인된다.

왜 Firebase Custom Token을 선택했을까?

1. 자체 인증 로직과 Firebase Auth를 유기적으로 연결할 수 있음
2. Firebase의 보안 기능(예: Firestore 규칙, FCM 등)을 그대로 활용 가능
3. 프론트엔드와 백엔드 간의 인증 책임을 분리할 수 있음

유의점

1. 커스텀 토큰의 유효기간은 1시간이므로 자동 로그인 시 토큰 갱신 로직 필요했음
2. 보안상 중요한 로직은 모두 Node.js 에서 처리

(1)	 사용 기술

-	TableCalendar 패키지

(2)	주요 기능
-	캘린더 UI 제공
-	날짜 클릭 시 해당 날짜의 일정 또는 기록 표시
-	일정 추가 , 삭제 기능 구현(왼쪽으로 슬라이드)
-	파이어베이스 연동을 통해 사용자의 일정 데이터를 Firebase에 저장 및 조회

2.4.	커뮤니티 
단순한 게시판 기능을 넘어, 좋아요 및 댓글 작성 기능까지 포함해 보다 실사용에 가까운 형태로 구성했다. 프론트엔드는 Flutter, 백엔드는 Node.js (Express), 그리고 데이터는 MySQL을 사용해 관리하고 있다.

(1)	 기본 CRUD 기능 
-	게시물 생성 (Create)
→  로그인된 사용자는 제목, 내용, 별명, 이미지 등을 입력해 새 게시물을 생성할 수 있다.	
→ 게시물 생성 시 사용자 정보(JWT 기반 인증 토큰을 통해 추출된 userId)가 함께 저장된다.

-	게시물 조회 (Read)
→ 커뮤니티 목록에서는 최신순으로 게시물들을 불러온다.
→ 단일 게시물 조회 시, 해당 게시물의 내용, 작성자, 작성일, 댓글 수, 좋아요 수 등을 함께 반환한다.

-	게시물 수정 (Update)
→ 게시물 작성자 본인만 수정할 수 있도록 서버에서 JWT 인증과 게시물 소유권을 검증한다.
→ 제목, 내용 등의 수정이 가능하며, 프론트에서는 해당 내용이 반영되도록 실시간 상태 업데이트 처리를 했다.

-	게시물 삭제 (Delete)
→ 마찬가지로 작성자 본인만 삭제가 가능하며, 삭제 시 관련 댓글과 좋아요 정보도 함께 정리된다.

(2)	 부가기능
-	좋아요 기능
→ 사용자는 각 게시물에 대해 좋아요(Like) 를 누를 수 있으며, 다시 누르면 좋아요 취소가 된다.
→ 서버에서는 사용자 ID와 게시물 ID를 기준으로 좋아요 상태를 토글하며, 현재 좋아요 수를 함께 반환한다.
→ 프론트에서는 버튼 클릭 시 상태를 즉시 변경하고, 좋아요 수를 동적으로 반영하도록 구현했다.

-	댓글 기능
→ 각 게시물에는 댓글을 작성할 수 있으며, 댓글은 실시간으로 리스트에 반영된다.
→ 댓글 작성 시 현재 로그인된 사용자의 정보(JWT에서 추출된 사용자 ID, 이름 등)가 함께 저장된다.
→ 서버에서는 게시물 ID를 기준으로 댓글 리스트를 조회하고, 프론트에서는 시간 순으로 정렬하여 보여준다.

* 인증 처리: JWT + Firebase
-	커뮤니티 기능은 로그인된 사용자만 이용할 수 있도록 구성했다.
-	Flutter에서는 로그인 시 발급받은 Firebase Custom Token을 통해 JWT를 생성하고, 이를 API 요청 시 헤더에 포함시켜 전달한다.
-	Node.js 서버에서는 이 JWT를 검증하여 userId를 추출하고, 이를 기반으로 커뮤니티 각 기능의 접근 권한을 제어한다.

2.5.	번개  
(1)	기본 CRUD 기능
-	 게시글 생성 (Create)
→  로그인된 사용자는 제목, 위치, 시간, 정원 등 정보를 입력해 새로운 번개 모집 게시글을 작성할 수 있다.
→ 게시글 생성 시 Firebase Authentication을 통해 추출한 UID와 displayName이 Firestore에 함께 저장된다.
→ 사용자는 글쓰기 다이얼로그를 통해 입력한 내용을 제출하면, Firestore의 posts 컬렉션에 문서가 생성된다.

-	게시글 조회 (Read)
→ 홈 화면에서는 카테고리별 또는 전체 게시글을 최신순으로 정렬하여 조회한다. 
→ 리스트는 ListView.builder로 구성되며, 정해진 수만큼 데이터를 불러오고 More 버튼을 통해 추가 로드되며, 게시글에는 작성자 이름, 위치, 시간, 현재 신청 인원 수 등 상세 정보가 포함된다.

-	게시글 수정 (Update)
→ 게시글은 작성자 본인만 수정할 수 있으며, FirebaseAuth에서 현재 로그인한 UID와 게시글에 저장된 UID를 비교해 권한을 확인한다. 
→ 수정 시 CreatePost 다이얼로그를 재활용하며, 변경된 데이터는 Firestore의 .update() 메서드로 적용된다. 수정 후 전체 리스트를 자동 새로고침하여 변경사항이 즉시 반영된다.

-	게시글 삭제 (Delete)
→ 게시글 삭제 또한 작성자 본인만 수행할 수 있도록 UID를 검증한다. 
→ 삭제 확인을 위해 다이얼로그(AlertDialog)로 사용자 확인을 받고, Firestore 문서를 .delete()로 제거한다. 
→ 삭제된 게시글은 UI에서 즉시 제거되고, 전체 게시글 리스트도 새로 고쳐진다. 

(2)	부가기능-
-	신청 기능
→ 사용자는 게시글에 참여 신청을 할 수 있으며, 한 번 신청한 경우 버튼 상태가 "신청 완료"로 변경된다. 
→ 신청자는 Firestore의 applicants 배열에 UID와 displayName으로 저장된다. 
→ 모집 정원이 다 찼을 경우 버튼은 자동으로 "마감"으로 변경되며, 신청이 불가능하게 된다. 

-	신청자 보기
→ 작성자는 더보기 메뉴를 통해 신청자 리스트를 확인할 수 있다. 
→ 해당 리스트는 신청자의 이름을 기반으로 표시되며, Firestore에서 applicants 필드를 통해 조회한다. 

2.6.	광고(수익화)

2.7.	API 연동
	목표
 	API 연동으로 날씨, 뉴스, 음악, 영상을 제공한다.

	구현
-API 선택-
날씨: OpenWeatherMap의 날씨 및 대기상태 조회서비스를 사용한다.
뉴스: Newsdata.io, Naver 검색 API(뉴스 카테고리) 등 국내외 뉴스 제공 API를 사용한다.
음악 및 영상: Google Cloud Platform에서 제공하는 YouTube Data API v3를 사용한다.
 
-API 요청-
날씨: 사용자의 현재 위치(GPS) 또는 검색한 지역의 위경도/도시명 정보를 포함하여 API에 HTTP GET 요청을 전송(해당 기능은 Flutter의 geolocator패키지를 사용한다. 해당 위치의 위도와 경도를 반환한다)
뉴스 , 음악 및 영상: 인증을 위해 발급받은 API 키를 요청 헤더 또는 파라미터에 포함한다.
 	-데이터 수신 및 처리-
API 응답은 주로 JSON 또는 XML 형식으로 수신한다.(해당 프로젝트에서는 JSON을 사용한다)
수신된 데이터를 파싱하여 애플리케이션에서 사용할 수 있는 데이터 모델로 변환한다. 이 과정에서 필요한 정보(ex: 날씨: 온도, 뉴스: 작성날짜, 음악 및 영상: 영상 제목 등)를 추출한다.
 	- 오류 처리-
API 호출 실패, 네트워크 오류, 잘못된 지역 정보 등의 예외 상황에 대한 처리를 구현하여 안정성을 확보한다.
- 데이터 표시-
가공된 정보를 사용자 인터페이스(UI)에 적절한 아이콘과 함께 시각적으로 표현한다.
 
	API 공통 사항
비동기 처리: API 요청은 네트워크 통신을 수반하므로 async/await 등을 사용하여 비동기적으로 처리하여 UI의 응답성을 유지한다.
JSON 파싱: 수신된 JSON 데이터를 Dart 객체(모델 클래스)로 변환, 타입 안정성 및 코드 가독성을 높인다.
오류 처리: 네트워크 오류, API 키 인증 실패, 할당량 초과, 검색 결과 없음 등 다양한 오류 상황에 대한 예외 처리를 한다.
할당량 관리: 일일 사용량 제한이 있으므로, 불필요한 호출을 최소화하고, 가능하다면 캐싱 전략을 도입하여 효율적으로 API를 사용합니다. 할당량 초과 시 사용자에게 적절한 안내를 제공한다.
사용자 인터페이스(UI): 불러온 데이터 목록은 썸네일 이미지, 제목 등을 포함하여 사용자 친화적 표시한다. 로딩 상태, 오류 상태 등을 명확히 피드백한다.

이후 해당 프로젝트를 지속적으로 유지보수한다면, 쿼리를 최적화하여 데이터베이스 접근 부하를 줄이고, 더 많은 클라이언트의 요청을 안정적으로 처리할 수 있도록 개선할 계획이다. 특히 기존에 구축된 자체 회원가입 로직에 더해, 카카오 OS 로그인 기능을 도입해 사용자 접근성과 편의성을 더욱 높이고자 한다. 또한 앱 내 기능 간의 유기적인 연결성을 강화하여, 모든 페이지에서 서비스가 원활히 작동할 수 있도록 개선하고 물과 수면 데이터를 스마트 워치와 연동하는 기능을 통해 사용자 데이터 활용도를  높여 개인 맞춤형 서비스로 발전시킬 계획이다. 나아가 향후에는 이러한 기능들을 통합해 사용자의 일상과 웰빙을 더욱 풍부하게 지원하는 종합 서비스로 완성해 나가고자 한다.
프로젝트에 처음 참여하는 인원이 많았던 만큼 어려움과 시행착오를 겪었지만, 기대했던 바를 끝까지 완성해 냈다는 점에서 팀원 모두가 큰 성취감을 느꼈다. 또한, 다양한 기술 스택을 배우고 연동하는 과정을 통해 기술적으로 한층 성장할 수 있는 프로젝트였다. 그뿐만 아니라, 웹과는 다른 앱의 동작 과정을 이해하고, 기본적인 개념을 익힐 수 있었다. 결과적으로 앱 기획, 설계, 개발까지 모든 과정을 직접 경험하며 한 단계 성장한 계기가 되었다.
